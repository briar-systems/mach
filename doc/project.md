# Project structure

How the compiler's source is laid out, what each area is for, and where a new
module goes. The language itself is described under [language/](language/README.md),
and the reference for every module is generated by `mach doc` into
[mach/](mach/README.md).

## The repository

```
src/        the compiler
dep/        its dependencies, each a pinned checkout
doc/        language/ and this page are written by hand, mach/ is generated by `mach doc`
dist/       the install scripts
out/        build output, never committed
mach.toml   the manifest: targets, profiles, the two artifacts and the dependencies
```

mach is the front end and the driver. The back end lives in three dependencies
under `dep/`: `mirl` is the IR and everything from legalisation to the frame,
`masc` is the machine tables and the assembler, and `mink` is the object formats
and the linker. `std` is the standard library, and `yaml`, `toml`, `json`,
`deflate`, `zstd` and `crypto` are the packages the compiler reads and writes its
files with.

## The source tree

`src/` is divided into areas. Each area is a directory with its root module
beside it: `src/lower.mach` is `mach.lower` and `src/lower/expr.mach` is
`mach.lower.expr`. The root module's docstring says what the area is, and the
generated reference prints it at the top of the area's page. Where an area has
nothing to declare at its root, the root module holds that docstring alone.

The areas are listed from the bottom up. A module imports from its own area and
from the areas listed before it, never from one listed after it. The one
exception is the ring described below the table.

| Area | What it is |
| --- | --- |
| `base/` | What every other area is written in: the allocation refusal, failures and diagnostics, interned strings and handles, source locations and the providers source text comes from, and plain utilities (array growth, checked arithmetic, 128-bit integers, floats, the binary codec, fingerprints, durations, the compiler's version). Nothing here knows the language or a build. |
| `report/` | How running work reports itself: the status a phase ends with, the progress readout a command renders, and the results of a test run. |
| `host/`, `host.mach` | The operating-system boundary: the primitives whose spelling differs by host, supervised child processes and their environment, directory listings, and how an output file reaches its final name. |
| `session/`, `session.mach` | The state one compiler process keeps across its work: the session, the module table, the query database, what is retained between builds, and the files a build embeds. |
| `type/`, `type.mach` | The type system: types, their kinds, fields and shapes, the queries over them, and deprecation notices. |
| `target/`, `target.mach` | What a target is: its inputs and defaults, the resolved target, its facts, tags and baselines, and the capability each constant-time operation needs of it. |
| `manifest/` | `mach.toml`: its schema and model, loading, the selection of targets, profiles and artifacts, templates, steps, and edits. |
| `front/` | The front end: the lexer, the parser and the syntax tree, module loading and name resolution, comptime evaluation, decorators, type checking (`sema/`), and doc comments. |
| `lower/`, `lower.mach` | Lowering of checked modules into mirl's IR, with what a build declares about linkage and placement. |
| `compile/`, `compile.mach` | Compiling one project for one target: the project's state, the front end's products, the lowering passes, the hand-off to mirl, the object cache, the demand for generic instances, the dependency closure, and entry builds. |
| `build/` | Running a build: the plan of units and phases, the engine, emission and link, the steps a manifest declares, and tests. |
| `package/`, `package.mach` | Dependencies, behind `mach dep` and `mach init`: resolution, pins, pulling and verification. |
| `tool/` | Whole-source tools built on the front end: the formatter, the migrator and the documentation generator. |
| `cli/` | The command line: arguments, one module per command under `cmd/`, and the rendering of diagnostics and progress. |
| `bin/` | The entry of the `mach` executable. |
| `editor.mach`, `lib/` | The analysis surface a language server builds on, and the entry of the `editor` artifact that keeps it checked, documented and built. |

### The ring

`session`, `type`, `target` and `manifest` import each other, so the order of
those four in the table is not a strict one.

- The session holds the type store, and the type queries read the session
  (`session` imports `type`, and `type/query/` imports `session`).
- A target's facts are stated over type shapes (`target/facts` imports
  `type/shape`), and the manifest is stated over targets.
- An embedded file's path is expanded as a manifest template (`session/embed`
  imports `manifest/template`), and the manifest's model records the query
  database's revision of its source (`manifest/model` imports `session/query`).

No other pair of areas imports each other. A change that would add a second
ring belongs in a lower area or is shaped wrong.

## Where a module goes

- In the lowest area whose description fits it. A utility that knows nothing of
  the language or a build is `base/`, even when only one area uses it today.
- A module begins with a module docstring that says what it is, before any
  import ([documentation.md](language/documentation.md#module)).
- A module is imported under its own name, or as `parent_leaf` where that name
  is taken: `base_source` for `mach.base.source`, `mach_target` for
  `mach.target`. The formatter sorts and aligns the import blocks.
- An artifact's entry is a file under `bin/` or `lib/` and holds nothing else.
  A consumer of the compiler's source imports modules by their path.

## Finding things

| To change | Look in |
| --- | --- |
| A diagnostic's key or severity | `base/diagnostic/kind.mach` |
| The grammar | `front/lexer.mach`, `front/token.mach`, `front/parser/` |
| Type checking | `front/sema/` |
| Comptime evaluation | `front/comptime.mach`, `front/comptime/` |
| What a decorator accepts | `front/decorator.mach` |
| The IR a construct lowers to | `lower/` |
| The object cache and its keys | `compile/cache.mach`, `compile/cache/` |
| The manifest's keys | `manifest/schema.mach` |
| A command or its flags | `cli/cmd/`, `cli/args.mach` |
| The formatter | `tool/format.mach` |
| What `mach doc` writes | `tool/doc.mach`, `tool/doc/` |
| `mach migrate` | `tool/migrate.mach`, `front/transition.mach` |
| The compiler's version | `base/version.mach` |
